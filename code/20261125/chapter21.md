8비트 CPU는 바이트 단위로 동작하지만 16비트 메모리 주소를 생성할 수 있습니다.
8비트 CPU는 16비트 메모리 주소를 처리할 수 있으며, 다른 디지털 컴퓨터와 마찬가지로 다양한 산술, 논리 작업을 처리합니다.
최신 16,32,64비트 CPU는 8비트 CPU보다 같은 작업을 더 빠르게 처리하며 동영상 디코딩 처럼 속도가 중요한 경우 차이를 만듭니다.
8비트 CPU는 바이트 단위로 연산하지만, 16비트 숫자를 더하는 경우처럼 여러 바이트의 숫자도 처리할 수 있습니다.

명령어 코드와 데이터가 뒤섞여 있는 메모리는 해석하기 어렵습니다.
이 프로그램은 두 16비트 값을 낮은 바이트와 높은 바이트끼리 각각 더해서 메모리에 저장하는 컴퓨터 프로그램입니다.
명령어 코드 값은 임의로 값을 부여한 것이 아닌, 인텔 8080 마이크로 프로세서에서 구현된 명령어 코드를 사용했습니다.
CPU를 설계하는 과정에서 인텔 8080 프로세서를 모델로만 사용할 것이며, 구현된 명령어 코드의 절반 남짓만 구현할 것입니다.
컴퓨터 심장에서 일어나는 일을 잘 알게될 것입니다.
이 코드들을 명령어 코드 혹은 동작 코드 혹은 오피코드라고 부르며 기계어라고도 알려져있습니다.
8080의 명령어 코드는 1바이트만 사용하지만, 그 뒤에 바이트 값이 더 필요한 2바이트 명령어나 3바이트 명령어는 길이가 가변적이므로 CPU 설계를 복잡하게 만듭니다. 
많은 경우 메모리에서 코드와 데이터를 뒤섞어서 배치하는 방법보다 코드의 데이터를 별도의 영역에 두는 것이 더 좋습니다.

CPU의 구성요소중에서 ALU(산술 논리 장치)는 덧셈, 뺄셈과 여러가지 작업을 수행합니다.
8비트 CPU에 있는 ALU를 이용해서 8비트보다 더 큰 숫자끼리 덧셈, 뺄셈을 처리하려면 바이트 단위로 연산해야 하며, 자리 올림수를 사용해야 합니다.
뺄셈에서는 자리올림수보다는 빌림수가 더 정확합니다.
이전의 덧셈 혹은 뺄셈에서 발생한 자리 올림을 비트값으로 저장함으로써 ALU가 다음 연산을 처리할 때 자리올림을 사용할 수 있습니다.

411p
자리올림을 처리하는 연산이 더 복잡합니다.
32비트 숫자를 더하는 경우 최하위 바이트부터 연산해나갈 때마다 자리올림 플래그로 기록하고 다음 바이트끼리 덧셈할 때 자리올림 플래그를 사용합니다. 
한 쌍의 32비트 숫자를 더하려면 더하기 연산 1개와 자리올림 더하기 연산 3개가 필요합니다.
2의 보수를 사용한다는 것을 제외하면 뺄셈도 비슷하게 자리올림을 사용합니다.(빌림수가 없으면 자리올림 플래그가 1 빌림수가 있으면 0)
