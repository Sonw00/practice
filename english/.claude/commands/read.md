---
description: 영어 문서를 한 문장씩 해석하고 단어·문법 후보를 뽑는다
argument-hint: <URL 또는 영어 본문>
---

입력: $ARGUMENTS

CLAUDE.md의 "후보 선정 기준"과 "기록 형식"을 따른다.

## 1. 본문 준비

- 입력이 URL이면 WebFetch로 가져와 본문만 남긴다. 메뉴, 광고, 푸터, 사이드바는 버린다.
- 코드 블록은 해석하지 않고 `(코드 생략)`으로 한 줄 표시만 한다.
- `known.md`와 `vocab.md`를 먼저 읽어 둔다.
- 본문이 40문장을 넘으면 약 30문장 단위로 나눠 진행하고, 한 부분이 끝날 때마다 "계속할까요?"라고 묻는다. 번호는 부분이 바뀌어도 이어서 매긴다.

## 2. 문장별 해석

문장마다 다음 형식으로 출력한다. 제목과 소제목도 한 문장으로 취급한다.

```
**[1]** The runtime *mitigates* contention by sharding the task queue.
→ 런타임은 작업 큐를 샤딩하여 경합을 완화한다.
- W1 `mitigate` (v.) 완화하다, 줄이다

**[2]** Having *ruled out* the scheduler, we focused on the allocator.
→ 스케줄러를 원인에서 배제한 뒤, 우리는 할당자에 집중했다.
- W2 `rule out` (phr. v.) 배제하다, 제외하다
- G1 완료 분사구문 `Having p.p., S V`: 주절보다 먼저 일어난 일 ("~한 뒤에")
```

G 줄은 문법 후보가 있는 문장에만 쓴다.

- 해석은 직역보다 자연스러운 한국어를 우선하되, 문장 구조가 어려우면 괄호로 구조를 짧게 덧붙인다.
- 단어 후보는 원문에서 `*기울임*`으로 표시하고 문장 아래에 `W번호`로 적는다.
- 이미 vocab.md에 있는 단어는 `- `word` (복습 중) 뜻` 형식으로만 적고 번호를 붙이지 않는다.
- W, G 번호는 문서 전체에서 1부터 이어서 매긴다.

## 3. 저장

`articles/YYYY-MM-DD-<slug>.md`에 저장한다. slug는 문서 제목을 영어 소문자와 하이픈으로 3~5단어로 줄인 것이다.

```
# <문서 제목>

- URL: <원본 URL 또는 "붙여넣음">
- 읽은 날: YYYY-MM-DD

<2단계 출력 전체>
```

## 4. 후보 요약과 선택 요청

마지막에 다음을 출력하고 멈춘다.

```
### 단어 후보
W1 mitigate · W2 rule out · W3 in lieu of ...

### 문법 후보
G1 완료 분사구문 · G2 관계대명사 생략 ...

실제로 몰랐던 것을 골라 주세요. 예: `W 1,3 G 2` / `W all` / `없음`
선택하지 않은 단어는 known.md로 이동합니다.
```

사용자가 답하면 CLAUDE.md의 "후보 선택 응답 처리"대로 기록한다.
